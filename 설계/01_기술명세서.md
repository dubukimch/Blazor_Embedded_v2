# Smart Grow IoT·Unity 통합 기술 명세

## 1. 목표와 범위

이 문서는 `MudBlazorWebApp240916` 통합 앱의 기준 아키텍처를 정의한다. 목표는 다음 네 가지다.

1. Arduino, ESP32, Raspberry Pi를 MQTT 토픽 프로필 형태로 추가한다.
2. MQTT TCP 연결은 서버에서만 수행하고 브라우저는 HTTP/SSE를 사용한다.
3. 하나의 정규화 이벤트로 Blazor 차트와 Unity WebGL을 동시에 갱신한다.
4. 네트워크 실패, 잘못된 입력, 페이지 이동을 정상적인 상태 전이로 처리한다.

## 2. 논리 아키텍처

| 계층 | 구성요소 | 책임 |
| --- | --- | --- |
| Edge | Arduino / ESP32 / Raspberry Pi | 센서 발행, 명령 구독 |
| Broker | MQTT 3.1.1 또는 5 호환 브로커 | 토픽 라우팅, QoS 전달 |
| Server | `MqttGateway` | 연결·구독·발행, payload 제한, 상태 관리 |
| Server | `TelemetryStreamBroker` | 브라우저별 bounded stream fan-out |
| Server | `DeviceModuleRegistry` | 장비 프로필 원자적 JSON 저장 |
| API | `/api/iot/*` | 상태/명령/모듈/SSE 계약 |
| Client | `IoTApiClient` | Server/Auto/WASM 공통 HTTP 접근 |
| UI | Dashboard / Devices | 운영 화면, 차트, 오류 피드백 |
| WebGL | `unityBridge.js` | Unity 인스턴스 보관, 양방향 호출, 수명주기 정리 |

브라우저에 MQTTnet을 두지 않는다. 일반 MQTT TCP(1883)는 브라우저 샌드박스에서 직접 사용할 수 없고, 브라우저 Ping 역시 지원되지 않기 때문이다.

## 3. 통신 계약

### REST API

| 메서드 | 경로 | 입력/출력 |
| --- | --- | --- |
| GET | `/api/iot/status` | 브로커 상태, 토픽, 메시지 수 |
| POST | `/api/iot/connect` | host, port, topics, 선택적 사용자명/암호 |
| POST | `/api/iot/disconnect` | 현재 MQTT 연결 종료 |
| POST | `/api/iot/publish` | topic, payload, qos, retain |
| GET/POST | `/api/iot/modules` | 모듈 목록/등록 |
| DELETE | `/api/iot/modules/{id}` | 모듈 삭제 |
| POST | `/api/iot/unity` | Unity 발신 데이터를 스트림과 MQTT에 반영 |
| GET | `/api/iot/events` | `text/event-stream`, event 이름 `telemetry` |

### `TelemetryEnvelope`

```json
{
  "topic": "farm/bed-01/telemetry",
  "payload": "{\"temperature\":23.8,\"humidity\":61}",
  "source": "mqtt",
  "receivedAt": "2026-09-03T00:00:00Z",
  "values": {
    "temperature": 23.8,
    "humidity": 61
  }
}
```

- `payload`: 원문을 보존한다.
- `values`: 차트에 사용할 수 있는 최상위 숫자 속성만 포함한다.
- scalar payload는 토픽 마지막 segment를 key로 사용한다.
- 텍스트 명령은 정상 payload이며 `values`가 비어 있을 수 있다.
- 최대 발행 payload는 256KB다.

## 4. MQTT 규칙

- 구독은 QoS 1을 요청한다.
- 발행 QoS는 0, 1, 2를 허용한다.
- 발행 토픽에는 `+`, `#` 와일드카드를 허용하지 않는다.
- 연결마다 고유 client id를 생성하고 clean session을 사용한다.
- 브로커 실패는 `ApiResult`와 `MqttGatewayStatus.LastError`로 UI에 노출한다.
- 자격 증명은 요청 중에만 사용한다. 모듈 JSON과 로그에 기록하지 않는다.

권장 토픽:

```text
farm/{deviceId}/telemetry
farm/{deviceId}/temperature
farm/{deviceId}/humidity
farm/{deviceId}/command
farm/{deviceId}/state
```

## 5. Unity WebGL 계약

Blazor → Unity:

```text
unityInstance.SendMessage("BlazorBridge", "OnTelemetry", envelopeJson)
```

Unity 장면은 `BlazorBridge` GameObject와 `public void OnTelemetry(string json)` 메서드를 제공해야 한다. 기존 빌드에 해당 객체가 없으면 JS 브리지는 경고를 남기고 Blazor 차트는 계속 동작한다.

Unity → Blazor:

```text
window.unityBridge.publishFromUnity(topic, payload)
  → VirtualFarm.ReceiveUnityMessage
  → POST /api/iot/unity
  → SSE + MQTT
```

Unity의 LED/Water/Air/Memo 레거시 `.jslib` 함수명은 호환 wrapper로 유지한다.

## 6. 오류·복구 기준

| 상황 | 기대 동작 |
| --- | --- |
| 브로커 접속 실패 | HTTP 400 + 사용자 메시지, 서버는 계속 실행 |
| 브로커 미연결 발행 | 명령 버튼 비활성 또는 명시적 오류 |
| 잘못된 JSON payload | 원문 이벤트 유지, `values`만 빈 객체 |
| 느린 브라우저 | subscriber별 128개 bounded queue, 오래된 항목부터 폐기 |
| SSE 단절 | 브라우저 `EventSource` 자동 재접속 |
| 페이지 이동/프리렌더 dispose | JS reference가 생성된 경우에만 정리 |
| Unity 로드 실패 | 화면 오류 메시지, 나머지 Blazor UI 계속 사용 |
| 모듈 파일 손상 | 빈 registry로 기동하고 경고 로그 기록 |

## 7. 보안 경계

현재 앱은 로컬·신뢰 네트워크용이다. 인터넷 공개 전 필수 작업:

- `/api/iot/*` 인증 및 역할별 publish 권한
- HTTPS와 MQTT TLS, 서버 인증서 검증
- CSRF/Origin 정책 검토 및 요청 rate limit
- MQTT host allowlist 또는 관리 승인 흐름
- 비밀 관리자에 MQTT 암호 저장
- 토픽별 ACL과 감사 로그

## 8. 검증 기준

- `dotnet build MudBlazorWebApp240916/MudBlazorWebApp240916.sln -c Release`: 경고 0, 오류 0
- GET status, module CRUD, 모든 화면/JS/Unity 자산 HTTP 200
- `POST /api/iot/unity` 이후 SSE에 정규화된 숫자 map 수신
- Dashboard 샘플 이벤트 후 KPI·차트·payload inspector 갱신
- 실제 브로커 환경에서는 connect, subscribe, publish, disconnect를 추가 검증
