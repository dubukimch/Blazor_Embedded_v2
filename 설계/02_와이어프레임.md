# Smart Grow 화면 설계

## 공통 셸

```text
┌────────────────────────────────────────────────────────────┐
│ ☰  SG  Smart Grow                         Gateway ready ◐ │
├──────────────┬─────────────────────────────────────────────┤
│ WORKSPACE    │                                             │
│ Greenhouse01 │                PAGE                         │
│              │                                             │
│ Overview     │                                             │
│ Telemetry    │                                             │
│ Modules      │                                             │
│ Unity twin   │                                             │
│              │                                             │
│ data-flow    │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

- 데스크톱은 고정 drawer, 모바일은 접이식 drawer를 사용한다.
- 현재 메뉴는 primary tint로 구분한다.
- 밝은/어두운 테마 모두 동일한 정보 위계를 유지한다.
- 성공/실패 메시지는 우측 하단 toast 영역에 표시한다.

## Overview `/`

```text
┌─────────────────────────────┬──────────────────────────────┐
│ 센서에서 디지털 트윈까지   │ LIVE PIPELINE                │
│ 하나의 데이터 흐름으로     │ Edge → Broker → Experience   │
│ [실시간 데이터] [모듈 추가]│                              │
└─────────────────────────────┴──────────────────────────────┘
┌────────────┐ ┌────────────┐ ┌────────────┐
│ MQTT       │ │ SSE        │ │ Unity      │
└────────────┘ └────────────┘ └────────────┘
┌────────────┐ ┌────────────┐ ┌────────────┐
│ Telemetry  │ │ Modules    │ │ Twin       │
└────────────┘ └────────────┘ └────────────┘
```

첫 화면은 기능 설명보다 운영 동선을 우선한다. 주요 버튼은 키보드 접근 가능해야 한다.

## Telemetry `/Dashboard`

```text
┌──────── MQTT broker ────────┐ ┌─ KPI × 4 ──────────────────┐
│ host / port / topics        │ │ Temp  Humidity  Soil  Count│
│ [연결] [해제]               │ └────────────────────────────┘
├──────── Command ────────────┤ ┌─ Live line chart ──────────┐
│ topic / payload             │ │                            │
│ [발행] [샘플 데이터]        │ └────────────────────────────┘
└─────────────────────────────┘ ┌─ Latest payload ───────────┐
                                └────────────────────────────┘
```

상태 정의:

- offline: 연결 버튼 활성, 발행/해제 비활성
- connecting: 중복 요청 방지
- online: host:port 표시, 발행 가능
- stream reconnecting: 차트는 마지막 값을 유지
- message: 최근 24개 지점과 원문 payload 표시

## Device modules `/Devices`

```text
┌──────── 새 모듈 ────────────┐ ┌──────── 연결 프로필 ───────┐
│ 이름 / 종류 / 장비 주소     │ │ ARD  Sensor A              │
│ MQTT host / port            │ │      host:1883  [연결] [×] │
│ telemetry / command topic   │ ├─────────────────────────────┤
│ [모듈 추가]                 │ │ PI   Gateway B             │
└─────────────────────────────┘ └─────────────────────────────┘
```

- 입력은 즉시 모델에 반영해 포커스 상태와 무관하게 제출된다.
- IP 주소는 선택값이다. 브로커가 DNS 이름인 환경을 지원한다.
- 모듈 삭제는 id 기반이며 저장 파일에 즉시 반영한다.

## Unity twin `/VirtualFarm`

```text
┌────────────────────────────────┬───────────────────────────┐
│ GREENHOUSE / LIVE SCENE        │ BLAZOR OVERLAY            │
│                                │ Live sensor chart         │
│         Unity canvas           ├───────────────────────────┤
│                                │ LED / Water / Air         │
│                                │ Latest bridge event       │
└────────────────────────────────┴───────────────────────────┘
```

- Unity canvas는 16:9를 유지하고 전체 화면 버튼을 제공한다.
- Blazor 차트는 Unity canvas 옆에 항상 표시해 Unity 로드 실패 시에도 데이터를 볼 수 있게 한다.
- 1180px 아래에서는 Unity 위, 차트/제어 아래의 단일 열로 전환한다.
- Unity가 요청한 Blazor panel 이름은 비차단 callout으로 표시한다.

## 반응형·접근성 체크리스트

- 320px 이상에서 수평 페이지 스크롤이 없어야 한다.
- 모든 입력은 label 또는 접근 가능한 이름을 갖는다.
- 색상만으로 online/offline을 구분하지 않고 텍스트를 병기한다.
- 차트와 함께 최신 숫자 KPI 및 원문 payload를 제공한다.
- 로딩, 빈 상태, 실패 상태 모두 다음 행동을 설명한다.
