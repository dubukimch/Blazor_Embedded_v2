# 2026-06-22 MQTT/디바이스 탐색 버그 및 비효율 개선

## 작업 목적

MQTT 연결, 센서 페이로드 파싱, 디바이스 탐색 기능의 빌드 오류와 런타임 버그 가능성을 점검하고, 불필요한 반복 처리와 오래된 코드 흐름을 정리했다.

## 확인한 문제

- `DeviceDiscoveryService`의 중괄호와 반환 위치가 깨져 빌드가 실패했다.
- `MqttService.ConnectAsync`의 중괄호가 잘못 닫혀 포트/토픽 검증 이후 코드가 클래스 본문 밖으로 밀려나 빌드가 실패했다.
- `Devices.razor`에 이전 트리 UI 코드와 현재 `Device` 모델 기반 코드가 섞여 있어 메서드 구조와 UI 컬럼이 깨져 있었다.
- MQTT 기능 화면들이 쿼리 검증 실패 또는 MQTT 연결 실패 후에도 `OnMessageReceived`를 구독할 수 있어, 같은 Blazor circuit에서 이전 연결의 메시지를 잘못 처리할 가능성이 있었다.
- `SensorPayloadParser`가 필드 별칭을 찾을 때 `names.Any(...)`를 반복 호출해 작은 비용이지만 불필요한 중첩 순회를 수행했다.
- `LedControl.razor`에 사용하지 않는 조도 센서 배열이 남아 있었다.
- `LedControlComponent`가 제거된 `MqttService.ConnectAndGetTopicsAsync` API를 호출하고, 익명 이벤트 핸들러를 해제하지 않는 구조였다.
- Electron 부트스트랩과 레거시 `DataModel`에서 빌드 경고가 발생했다.

## 변경 내용

- `DeviceDiscoveryService`
  - 설정 주입(`DeviceDiscoveryOptions`)을 복구했다.
  - 후보 IP 생성 메서드 `GetCandidateIpAddresses()`를 테스트 가능한 형태로 유지했다.
  - `MaxConcurrency` 기반 동시성 제한을 추가해 한 번에 과도한 Ping/HTTP 작업을 만들지 않게 했다.
  - HTTP timeout, 진행률 보고, 안전한 JSON 파싱, 기본 MQTT topic 추출을 정리했다.

- `MqttService`
  - 깨진 중괄호를 복구했다.
  - 서버/토픽 입력을 trim 처리했다.
  - 성공 연결/발행/재연결 시 `LastError`를 정리해 이전 오류가 UI에 남지 않게 했다.
  - 사용하지 않는 `DeviceInfoResponse` 클래스를 제거했다.

- `Devices.razor`
  - 디바이스 탐색, MQTT 입력, 연결, 장비 설정 전송, 기능 화면 이동 흐름으로 단순화했다.
  - 중복 컬럼과 현재 모델에 없는 트리 UI 의존성을 제거했다.
  - 장비 이름 기반으로 LED, DHZ/DHT, Soil Moisture 화면을 선택하도록 정리했다.

- MQTT 기능 화면
  - `DhzChart.razor`, `SensorChart.razor`, `LedControl.razor`에서 MQTT 연결 성공 후에만 메시지 이벤트를 구독하도록 변경했다.
  - LED 발행 성공 후 이전 오류 메시지를 지우도록 변경했다.

- `SensorPayloadParser`
  - 별칭 목록을 대소문자 무시 `HashSet`으로 바꿔 반복 비교 비용을 줄였다.
  - 토양 습도 값에 `"615.0"`처럼 정수 의미의 문자열을 허용했다.
  - `"615.5"`처럼 실제 소수 값은 계속 거부하도록 테스트로 고정했다.

- 테스트
  - MQTT 쿼리 검증 테스트의 오류 메시지 기대값을 읽을 수 있는 문자열로 정리했다.
  - 센서 파서에 대소문자 별칭과 정수형 실수 문자열 케이스를 추가했다.

## 남은 확인 사항

- 실제 Arduino 장비와 MQTT 브로커가 연결된 환경에서 `/device_info`, `/configure_mqtt`, LED ON/OFF, DHZ/토양 습도 차트 수신을 수동으로 확인해야 한다.
- 장비 이름 문자열 기반 라우팅은 임시 호환 방식이므로, 장비 펌웨어가 `device_type` 또는 `capabilities` 같은 명시 필드를 제공하면 그 값 기반으로 바꾸는 것이 좋다.
