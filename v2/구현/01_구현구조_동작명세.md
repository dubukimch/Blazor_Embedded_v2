# IoT·Unity 통합 구현 구조 및 동작 명세

## 1. 활성 솔루션

```text
MudBlazorWebApp240916/
├─ ClassLibrary1/                         # 공유 API 계약
│  └─ DataModel/IoTContracts.cs
└─ MudBlazorWebApp240916/
   ├─ MudBlazorWebApp240916/              # ASP.NET Core 서버
   │  ├─ Program.cs
   │  ├─ IoTApi.cs
   │  ├─ App_Data/device-modules.json
   │  └─ Services/
   │     ├─ MqttGateway.cs
   │     ├─ TelemetryStreamBroker.cs
   │     └─ DeviceModuleRegistry.cs
   └─ MudBlazorWebApp240916.Client/       # Blazor UI
      ├─ Services/IoTApiClient.cs
      ├─ Pages/{Home,DashBoard,Devices,VirtualFarm}.razor
      └─ wwwroot/
         ├─ css/site.css
         ├─ js/iotBridge.js
         ├─ js/unityLoaderScript.js
         └─ Build/*
```

구형 `MqttService`, `DeviceDiscoveryService`, 제어 dialog 파일은 이력 보존을 위해 남겨 두되 현재 프로젝트의 컴파일 대상에서는 제외한다. 새 기능이 이 파일을 다시 참조해서는 안 된다.

## 2. 서버 시작

1. MudBlazor와 Razor Components를 등록한다.
2. `TelemetryStreamBroker`, `DeviceModuleRegistry`, `MqttGateway`를 singleton으로 등록한다.
3. Unity 확장자 MIME과 ETag 재검증 캐시를 설정한다.
4. `/api/iot/*` minimal API를 매핑한다.
5. Interactive Server/Auto/WebAssembly 컴포넌트를 매핑한다.

Unity build 파일명에는 콘텐츠 해시가 없으므로 모든 정적 자산을 `max-age=0, must-revalidate`로 제공한다. 브라우저는 ETag가 같으면 304로 재사용하고, Unity 재빌드 뒤에는 낡은 번들을 고정하지 않는다.

## 3. MQTT 수신 시퀀스

```text
MQTT broker
  → MqttGateway.ApplicationMessageReceivedAsync
  → payload 원문 보존 + 숫자 추출
  → TelemetryEnvelope 생성
  → TelemetryStreamBroker.Publish
  → subscriber별 bounded Channel
  → /api/iot/events SSE
  ├─ iotBridge.js → DashBoard.ReceiveTelemetry → MudChart
  └─ unityLoaderScript.js
       ├─ unityInstance.SendMessage(...)
       └─ VirtualFarm.ReceiveTelemetry → sidecar MudChart
```

메시지 handler는 UI 코드를 직접 호출하지 않는다. 느린 한 브라우저가 다른 구독자를 막지 않도록 subscriber마다 capacity 128 queue를 둔다.

## 4. 연결·발행 시퀀스

### 연결

1. UI에서 host, port, 쉼표 구분 topics를 입력한다.
2. `IoTApiClient.ConnectAsync`가 절대 API URL을 생성해 Server/Auto/WASM 모두에서 호출한다.
3. 서버는 host/port/topic을 검증한다.
4. 기존 연결이 있으면 종료한 뒤 새 client id로 연결한다.
5. 토픽별 QoS 1 구독 후 status를 갱신한다.

### 발행

1. 브로커 연결 여부를 검사한다.
2. 발행 토픽의 와일드카드와 payload 256KB 제한을 검사한다.
3. 요청 QoS를 MQTTnet enum으로 변환해 발행한다.
4. 실패는 `ApiResult.Success=false`로 사용자에게 전달한다.

## 5. 모듈 등록

- 저장 위치: `App_Data/device-modules.json`
- 쓰기 방식: `.tmp` 파일 완성 후 원본으로 replace
- 저장 필드: id, name, kind, address, mqttHost, mqttPort, telemetryTopic, commandTopic, createdAt
- MQTT 사용자명/암호는 저장하지 않는다.

브라우저 Ping 기반 자동 검색은 제거했다. 검색 대역 고정, ICMP 차단, WASM 제약 때문에 오탐과 장시간 지연을 만들기 때문이다. 향후 mDNS/SSDP 탐색을 추가할 경우 서버 hosted service로 구현한다.

## 6. Unity 브리지 수명주기

1. `VirtualFarm.OnAfterRenderAsync(firstRender)`에서 `DotNetObjectReference`를 만든다.
2. `unityBridge.initialize`에 instance reference를 전달한다.
3. Unity loader script를 한 번만 추가하고 완료 promise를 재사용한다.
4. 생성된 `unityInstance`를 보관한다.
5. SSE 이벤트마다 `BlazorBridge.OnTelemetry(json)`을 호출한다.
6. Unity `.jslib`은 `publishFromUnity(topic,payload)`를 호출한다.
7. 페이지 dispose 시 SSE와 .NET reference를 정리한다.
8. 정적 prerender 인스턴스는 reference가 없으므로 JS 정리를 시도하지 않는다.

## 7. API 수동 점검 예시

```powershell
$base = "http://localhost:5000"
Invoke-RestMethod "$base/api/iot/status"

$body = @{
  topic = "qa/telemetry"
  payload = '{"temperature":24.5,"humidity":61,"soil":72}'
  source = "unity"
} | ConvertTo-Json
Invoke-RestMethod "$base/api/iot/unity" -Method Post -ContentType "application/json" -Body $body
```

별도 터미널에서 `curl -N http://localhost:5000/api/iot/events`를 실행하면 `values`가 포함된 `telemetry` 이벤트를 확인할 수 있다.

## 8. 완료 조건

- 솔루션 Release 빌드 경고 0, 오류 0
- 네 화면과 두 JS bridge, Unity loader 자산 HTTP 200
- module add/list/delete 성공 및 재시작 후 유지
- SSE 연결과 JSON/scalar 정규화 성공
- Dashboard 샘플 버튼으로 KPI, chart, inspector 갱신
- 페이지 이동 시 서버/브라우저 예외 없음
- 실제 장비 인수 테스트에서는 broker 연결/재연결, QoS, retained message, 전원 복구를 별도 확인
